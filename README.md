# WholeBody Pose73 ONNX — pretrained pose, parallel training

姿勢推定用に学習済みのDWPose-t / RTMPose-tから、軽量な人物クロップ用2D・3Dモデルを作ります。COCO-WholeBodyの教師から用途に必要な73点を選び、H3WBの対応注釈で手指・足先・顔を含む3Dを学習します。複数のGitHub Actionsジョブが同じモデルに勾配を供給し、保存した共通状態から必要な学習量まで継続します。

開発元：[DaisukeDaisuke/Wholebody-onnx](https://github.com/DaisukeDaisuke/Wholebody-onnx)

| 用途 | GitHub Actionsから新規作成する配布先 |
|---|---|
| 公開モデル・ONNX・モデル情報 | [RabbitDaisuke/Wholebody-Pose73-20261102-a6fde3](https://huggingface.co/RabbitDaisuke/Wholebody-Pose73-20261102-a6fde3) |
| 非公開チェックポイント・勾配・継続情報 | [RabbitDaisuke/Wholebody-Pose73-20261102-a6fde3-checkpoints](https://huggingface.co/RabbitDaisuke/Wholebody-Pose73-20261102-a6fde3-checkpoints) |

このREADMEは構成と実行方法を説明します。URLの記載を学習・公開完了の報告とは扱いません。実績は公開時のモデルカード、学習記録、品質判定結果に記録します。

## モデルと入出力

| 項目 | 構成 |
|---|---|
| 初期重み | 公式DWPose-t / RTMPose-tのCOCO-WholeBody＋UBody学習済み重み。画像特徴と姿勢ヘッドを再利用 |
| 2Dモデル | CSPNeXt-t＋RTMCC / SimCC。元の133点から73点を選び、GAUを含めてfine-tuning |
| 3Dモデル | 座標とスコアを入力する幅512・残差MLP 2ブロックのlifter |
| 入力 | 人物1人のRGBクロップ、`float32 [N,3,256,192]`、値域0～1 |
| 2D出力 | `keypoints2d [N,73,2]`：クロップ内の正規化座標 |
| スコア | `confidence2d [N,73]`：各点の推定スコア。校正済みの可視確率ではない |
| 3D出力 | `keypoints3d [N,73,3]`：左右股関節の中点を原点とするカメラ座標、メートル |
| 導出出力 | `geometry2d [N,8,2]`、`geometry_confidence [N,8]`：手の基準位置と手足の画像面内の方向 |
| 3Dの導出出力 | `geometry3d [N,8,3]`：手の基準位置と手足の3D骨格方向。表面や法線を独立に学習した出力ではない |
| 複数映像 | 可変バッチ`N`に独立したカメラ・人物のクロップをまとめ、同じ重みを使用 |

[公式初期重み](https://download.openmmlab.com/mmpose/v1/projects/rtmposev1/rtmpose-t_simcc-ucoco_dw-ucoco_270e-256x192-dcf277bf_20230728.pth)と[公式設定](https://github.com/open-mmlab/mmpose/blob/main/configs/wholebody_2d_keypoint/rtmpose/ubody/rtmpose-t_8xb64-270e_coco-ubody-wholebody-256x192.py)を出典として記録します。256×192は学習済みの空間MLPとSimCC分類器の形状を維持するための入力です。`pose_architecture.py`は純粋なPyTorchへの移植です。

133点から73点への変更では最終convの該当チャンネルを選びます。GAUは点同士の関係を計算するため、点を除くと残した点の予測も変わります。元モデルの精度をそのまま引き継いだと見なさず、再学習と同じ検証データでの基準モデル比較を行います。

### 現在の73点の意味

| 部位 | 点数と定義 |
|---|---|
| 身体 | 12：左右の肩・肘・手首・股関節・膝・足首 |
| 指 | 40：片手5指×4点。手のルートは身体の手首と共有 |
| 足 | 6：左右の母趾先端・小趾先端・踵。足首は身体の点を共有 |
| 顔 | 15：口角と口の内側上下4点、鼻先1点、左右の目頭・目尻・上下まぶた8点、頬側の顔輪郭2点 |

73は現在の用途に合わせた教師の選択です。恒久的な点数目標ではありません。順序、元データのID、座標系、前処理と全出力は`schema.json`に記録します。

顔の左右は本人から見た左右です。目の中心は目頭・目尻から導出する基準で、瞳孔や視線の教師ではありません。頬側の点は顔輪郭であり、頬表面の中心ではありません。手の基準位置は手首と4つの非親指MCPから導出し、手の甲の表面を独立に学習した点とは扱いません。足の骨格から求める向きも、実測された足裏表面・接触・法線とは区別します。

## データと3Dの教師

| データ | 使用する内容 |
|---|---|
| COCO-WholeBody v1.0 | 2D教師。既定8,192画像内の有効な人物クロップを選択し、公式train/val分割を維持 |
| H3WB | 注釈の2D・カメラ3D対応から同じ73点を選択。mmからmに変換して股関節中心へ移動 |
| ASPset-510 | 関節・カメラ・分割情報。対応する身体12点だけを3D教師として使用 |
| ASPsetのRGB評価 | 学習に含まれないtest動画 `1e28/0001/left` の192フレーム。実画像から身体12点の3Dを評価 |

H3WBは複数視点から作成された全身注釈です。全点が物理マーカー測定であるとは記載しません。取得した公式NPZのS1・S5・S6は学習60,000件、S7は検証20,000件の候補で、有効性による除外後の実件数をmanifestに記録します。同じ被写体の全カメラと動作を同じ分割に保ちます。この構成はHuman3.6MのRGB画像を取得しません。H3WB注釈のMITと、Human3.6M画像の別条件を区別します。

実ファイルには`metadata`と`train_data`があり、bboxは付属しません。全133点の有効な2D座標の範囲から、縦横比0.75・余白倍率1.25のクロップ座標を作ります。lifterは学習時・推論時とも同じ股関節中心とRMSスケールの正規化を使います。

ASPsetに存在しない指・顔・足先ラベルは損失から除外します。H3WBでは有効な全73点を教師にし、身体だけの成績を全身精度と呼びません。lifterには位置の乱れ、部分欠落、スコアの変化を含む入力を与え、完全な正解2Dだけに依存した学習を避けます。使用件数、分割、選択ID、取得先、ファイルhashと変換内容を学習manifestに残します。

## 学習量と並列更新

旧設定の固定256更新は、20,233人物に対し1更新128人物なら約1.62 epoch相当にすぎません。現在はデータ件数から**2D 20 epoch相当、3D最低30 epoch相当**の必要更新数を算出します。既定の2D共通batchは512（2ワーカー×8人物×32蓄積）で、20,233人物なら791更新です。3Dのbatchはデータ源ごとの件数と必要な寄与量から決めます。時間や更新数だけを精度の保証として扱いません。

並列学習の前に、bootstrapの単独ジョブでlifterを30 epoch相当準備学習します。これは並列実績に含めません。そのOptimizer状態を引き継ぎ、後続の2ワーカーによる学習でさらに最低30 epoch相当の3D教師を処理します。準備学習と並列学習の寄与を別々に記録します。

各フェーズの2つのActionsジョブは同じ共通重みを読み、異なるシャードから勾配を計算します。rank 0が各ワーカーの寄与を集約し、共通のAdamWを1回更新します。ステップ、元の重み、ワーカーIDを対応付け、重複・別ステップの勾配を適用しません。

ワークフローは最大12の連続フェーズを用意し、必要更新数を8フェーズ分のチャンクへ割り当て、後続フェーズで時間切れ等からの残りを引き継ぎます。1フェーズの学習枠は最大300分で、モデル、Optimizer、進捗を再開します。失敗や時間切れを学習完了とは扱いません。

今回の新しい非公開リポジトリ内では、完了したフェーズの交換用ファイルを整理し、履歴を圧縮して転送用ストレージの増加を抑えます。初期重み、完全な現在のOptimizer状態、前フェーズのチェックポイント、更新・来歴JSONは保持します。以前のモデル履歴には依存しません。

## 品質による公開判定

公開には学習予算の完了と、以下の品質条件が必要です。検証データは学習更新から分離します。2Dは同じ検証クロップで、元の姿勢学習済み教師と学習前の73点モデルを基準にします。

| 項目 | 既定の公開条件 |
|---|---|
| 身体2D | PCK@0.05 ≥ 0.80 |
| 左手・右手2D | それぞれ掌スケールPCK@0.20 ≥ 0.50 |
| 足2D | PCK@0.05 ≥ 0.70 |
| 顔2D | PCK@0.05 ≥ 0.80 |
| 各部位の基準モデル比較 | 教師と学習前73点モデルの成績をそれぞれ98%以上保持 |
| 誤差を含む2D入力からの身体3D | MPJPE ≤ 140 mm |
| 同じ条件での手3D | 手首基準のlocal MPJPE ≤ 40 mm |
| 同じ条件での足3D | 足首基準のlocal MPJPE ≤ 60 mm |
| 実RGBからの身体3D | ASPsetのheld-out test動画で、股関節中心基準のMPJPE ≤ 180 mm |

PCK@0.05はクロップ高さを基準にした画像面の距離で、手のPCK@0.20は正解の手首から中指MCPまでの長さで正規化します。表の注釈入力3D条件は、正解2Dと誤差を含む2Dの両方に適用します。有効な点・サンプル数、各データ源と評価入力条件も記録します。部位別の成績を集計し、身体の成績で手指・足先を代用しません。閾値、基準モデルとの差、判定理由を保存し、未達なら公開せず継続用状態を保持します。

正解2Dからのlifting、乱れや欠落を含む2Dからのlifting、RGB入力からの推定は評価条件が異なります。注釈入力のMPJPEをRGBから全処理を通した3D精度と読み替えません。品質達成と記載するのは実行結果が得られた後です。

RGB条件では1つのtest動画・1台のカメラから均等に選んだ192フレームを使い、モデル自身が推定した2D座標とスコアをlifterへ渡します。人物クロップには公式の正解bboxを使用するため、人物検出器の精度は評価しません。身体12点の結果を、手指・足先を含む全73点のRGB→3D精度や複数カメラでの実用精度とは呼びません。

## 推論コスト

姿勢学習済みtinyモデル、選択した出力チャンネル、共有の画像特徴、1つのlifterを使います。独立した人物・カメラを同じONNXセッションのbatchで処理できます。複数視点を幾何的に統合する機能ではありません。

256×192入力での構造からの計算値は次のとおりです。1回の乗算と加算の組を1 MACと数え、Conv・Linear・GAUの行列積を含めます。実行時には実際のモデルのshapeから同じ演算数を記録します。

| 構成要素 | 1人物あたりMAC | パラメータ数 |
|---|---:|---:|
| 共通CSPNeXt-t backbone | 327,907,584 | 2,348,700 |
| 73点RTMCC head | 118,080,128 | 2,042,059 |
| 73点lifter | 1,272,832 | 1,275,611 |
| 2D・3Dの導出行列 | 2,920 | 0 |
| 現在の全モデル | **447,263,464** | **5,666,370** |

比較用に、同じ実装の元の133点姿勢モデルは548,147,072 MAC、73点の姿勢部分は445,987,712 MACです。姿勢部分全体の削減は約18.6%です。公開上限は**500M MAC・8Mパラメータ**で、精度条件と合わせて判定します。

このMACにはpooling・正規化・活性化・softmaxなどの演算を含みません。教師は学習・評価時だけに使い、配布する推論モデルの数値へ加算しません。演算数をGPU使用率や実時間の測定として扱わず、複数ストリームでの実負荷はハードウェア・batch・実行頻度に依存すると記載します。[公式モデル表](https://github.com/IDEA-Research/DWPose)のFLOPs表記とも集計定義を区別します。

入力は人物クロップが前提です。人物検出、カメラアプリ、VRChat・SteamVR・VRM接続は含みません。3Dは相対姿勢であり、人物までの絶対距離やルート移動量を出力しません。小さな顔・指の精度には入力画像の情報量による限界があります。

## 実行と配布

Actions secretに`HF_TOKEN`を設定します。指定の`RabbitDaisuke`配下でリポジトリを作成・書き込みできる権限が必要です。作成処理はActions内で行い、トークンをソースやログへ出力しません。

GitHubの **Actions → Learn and publish Pose73 ONNX** を実行します。対象コード・設定の`main`へのpushも起動対象です。データ準備、姿勢学習済み重みの読込、継続可能な並列学習、品質判定、ONNX生成、公開を進めます。再開元のステップとその後の更新、各ワーカーの寄与を記録します。

公開物は`wholebody.onnx`、`schema.json`、`metrics.json`、学習・データ来歴、モデルカード、ライセンスとクレジットです。学習途中の重みを品質達成済みモデルとして公開しません。
